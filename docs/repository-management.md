# Правила ведения репозитория

Точка входа — [arcitecture.md](../arcitecture.md). Перед изменениями прочитать эту инструкцию, проверить `git status --short` и сохранить чужие незавершённые изменения.

## Где хранить файлы

| Каталог / файл | Назначение |
|---|---|
| `Soft/` | Исходники, миграции, DLL, Dockerfile и Compose приложения |
| `requests/` | Действующая схема API, контракты, исполняемые запросы и примеры |
| `tests/` | Постоянные автоматические тесты и runner |
| `docs/` | Постоянные инструкции по ведению репозитория, настройке и запуску |
| `tasks/TODO.md`, `tasks/TODO_Frontend.md` | Планы backend и frontend |
| `tasks/<ID>/` | Протоколы, исследования, разовые проверочные скрипты и материалы задачи |
| `tasks/<ID>/local/` | Скачанные runtime, архивы, бинарные выгрузки, крупные/временные материалы; вне Git |
| `logs/` | Все создаваемые вручную и runner-файлы `.log`; вне Git |
| `Soft/.env` | Единственный постоянный рабочий env-файл; вне Git |
| `Soft/.env.example` | Единственный безопасный шаблон настроек; в Git |

Не оставлять TODO, протоколы задач, папки `.artifacts*` и журналы в корне, `Soft`, `requests` или `tests`. В корне остаются точка входа `arcitecture.md` и необходимые корневые конфигурации инструментов. Прикладной код и постоянные тесты размещать в соответствующих исходных каталогах, не копировать в `tasks`.

Для новой задачи использовать её ID, например `tasks/SEC-02/verification.md`. Материалы прежних групповых проверок находятся в `tasks/bugfixes/` и `tasks/api-tests/`. Небольшие протоколы и полезные проверочные скрипты можно включать в Git; сборки, кэши и скачанные зависимости хранить в `local/`. Не перемещать файлы внутри чужих данных, Git, SDK или `bin`/`obj` при обычной уборке.

## Журналы и результаты

`tests/Run-ApiTests.ps1` автоматически записывает последний прогон в `logs/last-run.log`. Для отдельного запуска из корня использовать, например:

```powershell
docker compose --env-file Soft/.env -f Soft/Docker-compose.yml build *> logs/SEC-02-build.log
```

В Bash перенаправление эквивалентно `> logs/SEC-02-build.log 2>&1`. Для дополнительных журналов указывать ID задачи и назначение. Не создавать `.artifacts-*.log` или `tests/last-run.log`.

Не выводить рабочие пароли, токены, содержимое `.env`, необработанный `docker compose config` или полный `docker inspect`. Для Compose достаточно `config --quiet`. Подтверждённый результат кратко записывать в `tasks/<ID>/verification.md` с командой, итогом и ограничениями; журнал не заменяет протокол. Удалять только известные временные материалы своей задачи, не удалять Docker volumes с пользовательскими данными.

## Настройки и завершение работы

Docker и запуск с хоста используют один `Soft/.env`. Не создавать его копии под окружения. Compose задаёт `DB_HOST=postgres` внутри сети; в `.env` остаётся host-адрес `localhost`. Настройка и ротация пароля: [configuration.md](configuration.md). Временные env-файлы изолированных тестов допустимы только на время проверки и удаляются в `finally`.

После перемещения документов обновлять относительные ссылки, команды и пути в скриптах. Из `arcitecture.md` должны находиться актуальные планы, инструкция настройки и эта инструкция.
