# SEC-03 · Реализация до общей проверки

Дата: 26.10.2026. TODO не отмечен: пользователь разрешил запуск тестов только после общего просмотра реализаций.

`Login` принимает ровно один режим: `email` + `password` либо `refreshToken`. В обоих случаях возвращаются `accessToken`, `accessExpiresAt`, `refreshToken`, `refreshExpiresAt` и безопасный `user`. Права при каждом выпуске читаются из Auth-БД. Refresh передаётся в JSON, cookie нет. Клиент должен хранить пару в защищённом хранилище и передавать только по HTTPS, никогда через URL или журналы.

Refresh содержит 32 криптографически случайных байта в base64url. В `RefreshSessions` хранится только SHA-256 этого высокоэнтропийного значения, а также пользователь, UUID семейства/записи, создание, истечение, отзыв, ссылка на замену. Пароли обрабатывает отдельный CredentialService (SEC-04); SHA-256 refresh не является алгоритмом хранения паролей.

Credentials-вход, refresh и Logout блокируют строку пользователя `FOR UPDATE` внутри PostgreSQL-транзакции. Ротация сохраняет замену и гасит старый токен одной транзакцией. Повтор старого/отозванного токена отзывает всё семейство; отзыв фиксируется до возврата `INVALID_CREDENTIALS`. Два одновременных запроса не создают две рабочие ветви: один получает пару, второй обнаруживает повтор и отзывает её refresh. Потерянный успешный ответ нельзя безопасно повторить: клиент должен выполнить credentials-вход. Записи использованных токенов сохраняются как свидетельство повторов; автоматическая очистка истории сейчас отсутствует.

`Logout` защищён access JWT и отзывает семейство из подписанного `sid` только для подписанного `sub`; аргументов выбора другого пользователя/сессии нет. Повторный Logout идемпотентен. Другая credentials-сессия того же пользователя имеет другое семейство. PostgreSQL-триггер при изменении `PasswordHash` или переходе `Disabled=false→true` отзывает все семейства, в том числе при прямом обслуживании БД. Прозрачный rehash также отзывает прежние сессии; текущий credentials-вход после него создаёт новую. Обновление неизменившихся полей не отзывает сессии. Изменение Admin учитывается при следующем refresh.

Уже подписанный access продолжает работать до `exp` (с настроенным clock skew), в том числе после Logout/смены пароля/блокировки: онлайн-проверка Auth-БД для каждого запроса не вводилась. Refresh имеет скользящий срок JWT_REFRESH_DAYS от каждой выдачи; отдельного абсолютного срока семейства нет.

Добавлены API-проверки пары, истёкшего access, взаимоисключающих режимов, повторов/потери ответа, конкурентной ротации и Logout. Инфраструктурные проверки покрывают фактический SQL, хеши, FK замены, истечение, DB-отзыв, обновление прав, откат ошибки вставки и сохранение ротации/replay после restart. OWN-01 отдельно проверяет права на предметные записи.
