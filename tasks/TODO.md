# План доработки AglomSlagApplication

Дата статуса: 26.10.2026. Это учебный проект магистерского уровня, немного выше среднего. Нужны правильные расчёты, сохранность данных и понятный запуск за несколько минут. Выбирать простое решение по [правилам репозитория](../docs/repository-management.md); математические DLL не менять, работу вести локально.

Точка входа: [arcitecture.md](../arcitecture.md); [запросы API](../requests/README.md); [план интерфейса](TODO_Frontend.md). Подробные проверки: [багфиксы](bugfixes/verification.md), [первая ручная проверка](api-tests/verification.md). Отметка `[x]` означает проверенную работу, `[ ]` — оставшуюся; правка этого плана не закрывает задачи. Aglom исключён пользователем, BUG-08 выполнен частично.

Обычный запуск: заполнить один `Soft/.env` по шаблону и выполнить `docker compose --env-file Soft/.env -f Soft/Docker-compose.yml up -d --build`. Демонстрационные аккаунты создаются автоматически из `.env`; дополнительных обязательных команд и сертификатов нет. HTTP, GraphQL IDE, SDL и introspection доступны без входа; бизнес-методы, кроме Login, требуют JWT.

Приоритеты: **P0** — доступ и сохранность данных, **P1** — правильная работа и нужные функции, **P2** — удобство сопровождения. Сначала завершить защиту импортных оригиналов, затем ветвление, страницы и Excel, после — подключение интерфейса и общую проверку. IMP-01 завершить до первой загрузки реальных импортов. Один человек последовательно показывает обычного пользователя и администратора; нагрузочная инфраструктура и защита от всех возможных обходов не нужны.

## 4. Дочерние варианты

### [ ] VAR-01 · P1 · Добавить ветвление вариантов через `UpdateCalcVariant`

**Сценарий:** открыть вариант, изменить параметры/расходы, при желании рассчитать и сохранить как дочерний. Получить новую запись с новым ID; исходник и его компоненты не меняются. Допустимы несколько ветвей и копия дочернего варианта.

В модели уже есть nullable `ParentId`, `Parent/Children` и FK `DeleteBehavior.Restrict`. Повторно добавлять связь не нужно; сейчас input не задаёт родителя, update меняет существующую запись.

**Контракт команды:** добавить необязательный `parentId`, разрешить отсутствие `variantId` в режиме копии. Не путать аргумент с сохранённым полем результата: открыв ID 20 с родителем 10, для новой копии передать `parentId=20`.

| Аргументы | Результат |
|---|---|
| `parentId=null`, указан `variantId` | обычный update по правам, сохранённый `ParentId` не меняется |
| `parentId` указан и доступен | новая запись с этим `ParentId`; переданный `variantId` не используется как PK и не обновляется |
| `parentId` отсутствует в БД или недоступен | ошибка, без перехода к update или созданию корневой записи |
| оба ID отсутствуют | ошибка; новый корневой вариант создаёт `AddCalcVariant` |

`parentId=0` — конкретный ID, не отсутствие; отрицательные seed-ID тоже настоящие. Для обычного редактирования child передавать `parentId=null`, а не копировать поле из ответа чтения.

**Сделать:** разделить создание и update в `Mutation.cs`/`SlagModeQueryService.cs`, проверять правила и в сервисе записи. Для копии создавать новые `CalcVariant` и `ComponentVariant`, не переиспользовать и не удалять состав источника. Ключ варианта выдаёт БД, не «родитель + 1»; `ComponentId` ссылается на прежний справочник, `VariantId` компонентов — на новую запись.

Сохранять полный переданный набор: кокс/шлак/чугун, дату расчёта, имя и компоненты; пропущенное обязательное поле — ошибка, не ноль. Проверить печь, ссылки и доступ к непосредственному родителю; не менять происхождение при обычном update, не создавать цикл/ссылку на себя. Владелец новой копии — текущий пользователь, `IsImport=false`, время сохранения — новое UTC. Источник может быть импортным; его флаг остаётся `true`. Расчёт остаётся отдельной операцией, скрытый пересчёт не добавлять.

Вариант и компоненты сохранять полностью или без изменений. Вернуть новый ID, `parentId`, время, флаг, печь и состав; клиент открывает возвращённый ID. Сохранить FK `Restrict`: родитель с детьми не удаляется, ручная копия без зависимостей удаляется по правам. Импортный оригинал защищён независимо от детей. Чтение `Parent/Children` показывает доступное происхождение.

**Проверить:** обычный update; копию с отсутствующим, исходным и посторонним `variantId` (существующие записи не обновляются); две ветви и child от child; ручную копию импорта и её редактирование/удаление. Сверить весь источник до/после. Проверить недоступного/отсутствующего родителя, оба пустых ID, 0, действительный отрицательный ID, неверные компоненты, отказ записи и удаление родителя с детьми. После перезапуска дерево и ответы должны совпасть.

**Готово, когда:** сценарий «открыть → изменить → сохранить дочерний → открыть новый ID» работает, непосредственный источник и соседние ветви сохранны, права/защита импорта соблюдаются, обычный update работает как раньше.

## Границы работ и ещё не принятые решения

Предпросмотр Excel и экспорт одного выбранного варианта выполняются в браузере; сервер принимает исходный файл, проверяет права/данные и сохраняет. Серверные preview/confirm/export не требуются. Расчёт получает полный показанный пользователю набор параметров; отдельная команда «рассчитать по ID» не нужна.

Не входят в объём: контроль одновременного редактирования/version/ETag, сложное журналирование и readiness, разделение ролей PostgreSQL, отдельный журнал действий пользователей, распределённая/нагрузочная инфраструктура. Обычные понятные ошибки, права и сохранение без частичных изменений остаются обязательными. Поля происхождения импорта не требуют отдельной системы аудита.

До импорта согласовать E:HR или также C/D, полный набор показателей или подмножество, формулы без актуального сохранённого результата и отсутствующие обязательные значения (IMP-02); для BUG-08 — правило жидкого состояния. Владельцы, булев `Admin`, защита импорта для обеих ролей, клиентские предпросмотр/экспорт и Login с двумя режимами и JSON-парой уже согласованы.
