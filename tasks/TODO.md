# План доработки AglomSlagApplication

Дата статуса: 31.10.2026. Это учебный проект магистерского уровня, немного выше среднего. Нужны правильные расчёты, сохранность данных и понятный запуск за несколько минут. Выбирать простое решение по [правилам репозитория](../docs/repository-management.md); математические DLL не менять, работу вести локально.

Точка входа: [arcitecture.md](../arcitecture.md); [запросы API](../requests/README.md); [план интерфейса](TODO_Frontend.md). Подробные проверки: [багфиксы](bugfixes/verification.md), [первая ручная проверка](api-tests/verification.md). Отметка `[x]` означает проверенную работу, `[ ]` — оставшуюся; правка этого плана не закрывает задачи. Aglom исключён пользователем, BUG-08 выполнен частично.

Обычный запуск: заполнить один `Soft/.env` по шаблону и выполнить `docker compose --env-file Soft/.env -f Soft/Docker-compose.yml up -d --build`. Если используется инструмент для туннелирования трафика, добавить второй файл: `docker compose --env-file Soft/.env -f Soft/Docker-compose.yml -f Soft/compose.private-network.yml up -d --build`. Выбор подсети и переключение сети описаны в [настройке запуска](../docs/configuration.md). Демонстрационные аккаунты создаются автоматически из `.env`; дополнительных обязательных команд и сертификатов нет. HTTP, GraphQL IDE, SDL и introspection доступны без входа; бизнес-методы, кроме Login, требуют JWT.

Приоритеты: **P0** — высший приоритет: перенос полезного функционала референса, доступ и сохранность данных; **P1** — остальные нужные функции; **P2** — удобство сопровождения. Сначала выполнять блок REF ниже по зависимостям; IMP-01 завершить до первой записи реальных импортов. Все открытые REF имеют P0 по решению пользователя, их порядок задаёт последовательность, а не критичность дефекта. Один человек последовательно показывает обычного пользователя и администратора; нагрузочная инфраструктура не нужна.

Переносим инженерные сценарии в наш ASP.NET Core / GraphQL / EF Core / PostgreSQL и будущий браузерный клиент. Прямое подключение браузера к БД и WinForms не переносим. Шесть прежних задач сняты с активного плана; их исходные тексты и соответствие заменам — в [списке легаси](REF-PLAN/legacy.md). Снятие с плана не означает выполнение.

## Границы работ и ещё не принятые решения

Предпросмотр Excel и экспорт одного выбранного варианта выполняются в браузере; сервер принимает исходный файл, проверяет права/данные и сохраняет. Серверные preview/confirm/export не требуются. Расчёт получает полный показанный пользователю набор параметров; отдельная команда «рассчитать по ID» не нужна.

Контроль версии и история расчётных снимков теперь входят в REF-08. Не входят в объём: сложное журналирование и readiness, разделение ролей PostgreSQL, отдельный журнал действий пользователей, распределённая/нагрузочная инфраструктура. Обычные понятные ошибки, права и сохранение без частичных изменений остаются обязательными. Поля происхождения импорта не требуют отдельной системы аудита.

Первый объём REF-03 — исторические месяцы E:HR, без автоматического импорта C/D. Полноту модели, отсутствующие значения, кэши формул и технологические допущения зафиксировать в REF-01/03; для BUG-08 — правило жидкого состояния. Владельцы, булев `Admin`, защита импорта для обеих ролей, клиентские предпросмотр/экспорт и Login с двумя режимами и JSON-парой уже согласованы.
