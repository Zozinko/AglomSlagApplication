# План интерфейса AglomSlagApplication

Дата: 26.10.2026. Это план, интерфейс ещё не объявлен готовым. Делать простое учебное приложение по [правилам репозитория](../docs/repository-management.md): один человек последовательно показывает пользователя и администратора. [План сервера](TODO.md), [запросы API](../requests/README.md). При реализации сверяться с обновлённой схемой; библиотеку интерфейса и чтения XLSX выбрать тогда.

Обычный запуск backend — один `Soft/.env` и `docker compose --env-file Soft/.env -f Soft/Docker-compose.yml up -d --build`, demo-аккаунты создаются автоматически. Используется HTTP без сертификатов; IDE/SDL/introspection открыты, бизнес-методы кроме Login требуют JWT.

Общие правила: обычный пользователь работает со своими записями, администратор — со всеми владельцами. Реальные права проверяет API. Импортный оригинал `isImport=true` доступен только для чтения обеим ролям; эксперимент сохраняется как дочерний вариант (child) с `isImport=false`. Расчёт получает полный набор показанных в форме параметров. Предпросмотр Excel и экспорт одного варианта выполняет браузер; дополнительные серверные preview/confirm/export и черновики не нужны. Механизм одновременного редактирования и нагрузочные сценарии не требуются.

**Сделать:** экран Login с состоянием ожидания и понятной ошибкой. Использовать существующий контракт SEC-02/03: Login с логином/паролем или refresh-токеном, JSON-пара access/refresh, защищённый Logout. Передавать access через `Authorization: Bearer`, обновлять при истечении; при отказе refresh возвращать на вход. Токены и пароль не писать в URL, журналы и экспорт.

Показывать ID/`Admin` фактического пользователя. При выходе/смене аккаунта очищать его списки, выбор, форму и предпросмотр. Подключаться с разрешённого адреса по WEB-01, обрабатывать серверный запрет и GraphQL `errors` даже при HTTP 200. После неопределённого сетевого результата записи сначала проверить состояние, чтобы повтор не создал ещё одну копию/импорт.

**Проверить:** оба аккаунта по очереди, неверный пароль, истечение access, отказ refresh, Logout и смену пользователя. **Готово, когда:** вход/обновление работают, видна настоящая роль, чужие данные не остаются на экране и отказ не выглядит успехом.

## [ ] FE-VAR-01 · P1 · Просмотр параметров, расчёт и сохранение дочернего варианта

**Зависимости:** VAR-01, IMP-01, OWN-01, BUG-01/02/03/04, DTO-01.

**Сделать:** открыть полный набор кокса/шлака/чугуна и компонентов с единицами, владельцем, датой, ID, признаком импорта и непосредственным `parentId`; дать переход к доступному родителю/детям. Хранить исходные значения отдельно от рабочей формы. Правка формы сама по себе не сохраняет оригинал.

«Рассчитать» отправляет полный показанный ввод. После правки входов помечать прежние результаты как устаревшие до нового расчёта. Разделить действия:

- «Сохранить изменения» — обычный update доступного ручного варианта с `parentId=null`.
- «Сохранить как дочерний» — новый вариант по VAR-01: `parentId=ID открытого источника`, а не его прежний родитель; старый `variantId` не становится новым ID. После успеха открыть ID из ответа.

Для импорта обеим ролям недоступны обычное сохранение и удаление; изменить рабочие вводные, рассчитать и сохранить child можно. Ручные копии редактируются/удаляются по правам; администратор может менять чужую ручную запись. Для родителя с детьми показать серверный запрет удаления. При ошибке сохранять введённое и не показывать успех до подтверждения API.

**Проверить:** открыть источник → изменить → рассчитать → сохранить child → открыть новый ID; две ветви и child от child с правильными ID родителей. Изменить/удалить ручную копию, проверить неизменность оригинала. Повторить администратором с чужими записями и запретом на импорт.

**Готово, когда:** ясно, какие входы дали результат, источник отделён от правок, новая ветвь сохраняется правильно, импортная история остаётся неизменной.

## [ ] FE-IMP-01 · P1 · Предпросмотр файла и подтверждение импорта целиком на фронтенде

**Зависимости:** IMP-02/03, OWN-01, IMP-01, WEB-01. Сценарий: выбрать Excel → браузер читает `Шлак` → показать данные → подтвердить → отправить исходный файл обычному API импорта → показать отчёт. До подтверждения записи в БД нет; серверный предпросмотр не нужен.

**Сделать:**

1. Читать XLSX в браузере по согласованному соответствию ячеек и полей (IMP-02). Проверить лист, структуру, заголовки и значения; понятным сообщением отклонять повреждённый/неподдерживаемый файл. Параметры идут по строкам, варианты по колонкам: не смешивать C/D и исторические месяцы. Дать выбор печи и согласованной области импорта.
2. Обрабатывать формулы/сохранённые результаты по IMP-02, не выполнять макросы, внешние ссылки и код. Показывать периоды, количество вариантов, важные входы, единицы, печь, текущего владельца, предупреждения/ошибки с координатами. Значения исходного файла незаметно не исправлять.
3. До подтверждения хранить файл и предпросмотр только в браузере. Отмена/смена файла сбрасывает выбор без mutation и серверного черновика; смена аккаунта требует повторного выбора/проверки владельца. При смене файла или параметров прежнее подтверждение не действует.
4. После явного подтверждения отправить **тот же исходный файл** и выбранные параметры в авторизованный API. Клиентский разбор не заменяет серверную проверку. Показать реальный отчёт: ID/число сохранённых вариантов, повторы и причины отказа; список обновлять после ответа.

**Проверить:** `baseData/Без названия.xlsx`, контрольные ячейки/месяцы, неверный лист, пустое значение/отсутствующий результат формулы, нулевой расход, ошибка Excel, смена файла и отмена. Сверить клиентский разбор с backend: проценты, единицы, даты, пусто/ноль должны совпадать. Через Network проверить отсутствие отправки на импорт до подтверждения; после него сверить исходный файл/параметры, отчёт и сохранённые данные. Проверить отказ сервера после удачного предпросмотра.

**Готово, когда:** пользователь понимает состав загрузки, отменяет без записи и подтверждает сохранение через обычный импорт; подготовка предпросмотра целиком в браузере, итоговая проверка/запись — в API.

## [ ] FE-EXP-01 · P1 · Экспорт одного выбранного варианта в XLSX/CSV на клиенте

**Сделать:** сформировать в браузере файл одного выбранного сохранённого варианта из полного доступного DTO и результатов по тем же входам. Включить параметры/компоненты и расходы, единицы, печь, дату, владельца, ID/`parentId`, признак импорта. Массовая история и серверный метод экспорта не нужны.

Числа XLSX сохранять числами, названия — текстом, а не формулами. Для CSV согласовать разделитель, кодировку и экранирование. При несохранённых правках предложить сохранить вариант/child или отменить правки перед экспортом сохранённой записи. Если результата нет — указать это или предложить расчёт по просмотренным входам; старый результат не выдавать за новый. Имя файла понятное, без секретов.

**Проверить:** свой вариант и доступный администратору чужой, импорт и child, дроби/русские имена/запятые/кавычки/переносы. Открыть файл, сверить входы, компоненты, метаданные и результаты. **Готово, когда:** выгружается ровно одна показанная сохранённая запись, файл открывается обычным табличным приложением, токенов/паролей в нём нет.

## [ ] FE-QA-01 · P1 · Подготовить сценарий показа работы

**Проверить одним человеком по очереди:**

1. Вход пользователя → свои варианты → страницы/фильтры → входные параметры → правка/расчёт → сохранение child.
2. Импортный оригинал → запрет сохранения/удаления → доступное создание ручной копии.
3. Предпросмотр Excel → отмена без записи → повторный выбор/подтверждение → отчёт и новые записи.
4. Один вариант → экспорт XLSX/CSV → проверка файла.
5. Выход → вход администратора → разные владельцы → изменение чужой ручной копии → тот же запрет изменения импорта.
6. Ошибка API/истёкшая сессия → понятное сообщение без ложного успеха.

**Готово, когда:** сценарии воспроизводятся на учебном стенде с реальным API и правами. Готовый сервер сам по себе не закрывает предпросмотр, экспорт и остальные задачи интерфейса.
