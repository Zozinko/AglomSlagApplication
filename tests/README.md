# Автоматические тесты API

Из корня проекта выполните:

```powershell
./tests/Run-ApiTests.ps1
```

Скрипт собирает приложение, создаёт отдельную PostgreSQL 16, применяет миграции обеих БД, запускает API и проверяет все 19 корневых операций GraphQL. Используются настоящие математические DLL и БД. После проверки скрипт удаляет свой стенд. Ожидаемый результат — код завершения `0`; вывод сохраняется в `logs/last-run.log`. При ошибке показываются сообщения API и migrator. Команда `dotnet test` этот набор не запускает.

## Что нужно установить

Нужны Docker с Linux containers, Compose v2, PowerShell, Node.js 22+ и ASP.NET Core runtime .NET 10. Runtime нужен для проверки запуска из IDE в режиме Development. SDK .NET на компьютере не требуется: API, migrator и проверки паролей собираются в Docker. При первой сборке нужен доступ к реестрам образов и NuGet. Тесты Node.js используют встроенный `node:test`, дополнительные npm-пакеты не нужны.

Если runtime установлен вне `PATH`, задайте `API_TEST_DOTNET` абсолютным путём к `dotnet.exe` или `dotnet`.

## Что происходит при запуске

Для каждого прогона создаётся Compose-проект `aglom-api-tests-<случайный суффикс>`. PostgreSQL хранит данные в `tmpfs`, API запускается в Production по HTTP на случайном порту `127.0.0.1`. Для запуска с хоста БД также получает случайный порт на `127.0.0.1`. Пароли и ключ JWT создаются на время проверки. Рабочий `Soft/.env` не читается.

После миграций API автоматически создаёт демонстрационные аккаунты. Тесты получают токены настоящим входом и выполняются последовательно. Последними идут проверки запуска и остановки БД. При перезапуске контейнера тесты заново определяют порт Docker Desktop.

Стенд не использует контейнеры `aglom_*`, volume `postgres_data`, порт 5000 и сеть рабочего Compose. Проверки создают собственные записи и убирают их через `t.after`, не меняя начальные демонстрационные данные. В блоке `finally` скрипт удаляет контейнеры, сеть и собранные образы только своего проекта и восстанавливает прежние переменные окружения. Код `0` возвращается только после успешных тестов и очистки.

После принудительного завершения процесса очистка может не выполниться. Оставшийся тестовый проект можно найти через `docker compose ls`; точное имя есть в выводе запуска.

## Основные проверки

| Файл или группа | Что проверяется |
|---|---|
| `api/catalog.test.mjs` | чтение, создание, изменение и удаление печей и справочника; все поля состава; отсутствующие ID; запрет удаления используемых записей |
| `api/variants.test.mjs` | поля вариантов и компонентов, дата UTC, смена печи и состава, очистка состава, независимость сохранённого состава от справочника, удаление зависимостей; отсутствие частичных изменений при отказе |
| `api/calculations.test.mjs` | оба вида флюса агломерата и числовые поля отчёта; числовые результаты шлакового расчёта, суммы расходов и доли материалов; отказ при непригодных входных данных |
| `api/contract.test.mjs` | `hello`, публичные GET/SDL/introspection в Production, сравнение схемы, точный набор 5 query и 14 mutation, документы и JSON-примеры; ошибки структуры запросов |
| `api/persistence.test.mjs` | время создания, неизвестное время старых записей, ограниченная глубина связей, проверка имён и дат |
| `api/error-contract.test.mjs` | коды ошибок без SQL, входных значений и внутренних исключений; отказ при результате DLL, который нельзя вернуть как число |
| `api/calculation-roundtrip.test.mjs` | расчёт до и после сохранения; точный двоичный пример и допуски binary32 для десятичных входных данных |
| `api/authentication`, `api/sessions`, `api/ownership` | обязательный JWT, вход в смешанном документе и через псевдонимы/фрагменты, публичная схема; обновление токенов, повторное и одновременное использование, выход; права двух ролей |
| `requests-workflow.test.mjs` | запуск `requests/Invoke-GraphQL.ps1`: вход обеих ролей, отказ без токена, чтение, расчёт, сохранение, удаление, обновление токенов и выход |
| `infrastructure/runtime.test.mjs` | миграции прежней БД, SQL-типы и связи, перезапуск, настоящий отказ БД при сохранении, неправильные настройки и пароли, остановленный PostgreSQL, ошибка migrator, Development и другой порт |
| `infrastructure/secrets.test.mjs` | обязательные настройки, исключение env из Git и образов, чтение env в Development, приоритет окружения, прежние имена строк подключения, смена пароля БД без потери записей |
| `infrastructure/authentication`, `ownership`, `passwords`, `sessions` | настройки JWT, лимит входов, связи владельцев, запрет изменения импорта, создание аккаунтов без сброса паролей, хеши, смена и сброс пароля, блокировка, сроки сессий |
| `credentials` | стоимость проверки пароля и проверки неизвестного пользователя в SDK-контейнере (.NET CredentialChecks) |
| `api/helpers.mjs`, `compose.api-tests.yml`, `Run-ApiTests.ps1` | HTTP-клиент с таймаутом, обработка GraphQL errors при HTTP 200, подготовка данных, запуск и очистка стенда |

Запросы и JSON берутся из `requests/operations` и `requests/examples`; тесты подставляют ID созданных объектов. Для сохранённых `float` применяется допуск; порядок строк в списках не фиксирован. При изменении варианта проверяются актуальная печь и неизменность `saveTime`; у старых записей ожидается `null`.

Проверки расчётов подтверждают передачу данных через HTTP и DLL, числовые результаты и выводимые из входа суммы и доли. Они не заменяют научно утверждённые примеры расчётов. Защита при прямой работе с объектами БД (IMP-01), импорт (IMP-03) и создание дочерних вариантов (VAR-01) ещё не реализованы и не считаются проверенными.

## Обновление схемы и отладка

После намеренного изменения API обновите сохранённую схему:

```powershell
./tests/Run-ApiTests.ps1 -UpdateSchema
```

Скрипт получает публичный `/graphql?sdl` временного API и сохраняет `requests/schema.graphql`. Обычный запуск только сравнивает схемы. Необязательная серверная команда `--export-schema` выводит внутреннюю схему с директивами проверки доступа; в публичном SDL этих директив нет, поэтому текст может отличаться.

Для прямого запуска `.mjs` нужен `GRAPHQL_TEST_URL`: значения по умолчанию нет. Некоторые проверки также требуют тестовые токены, ключ, email, пароли и переменные Compose, поэтому полный скрипт проще. Для выбранного файла укажите адрес собственного отдельного стенда:

```powershell
$env:GRAPHQL_TEST_URL = 'http://127.0.0.1:<порт-тестового-API>/graphql'
node --test --test-reporter=spec tests/api/variants.test.mjs
```

`API_TEST_DB_PASSWORD` существует в окружении только во время прогона; без него тестовый Compose не запускается. Для проверки Docker-сборки скрипт временно создаёт вложенный env-файл и удаляет его в `finally`. Проверка Development копирует опубликованный API во временную папку, запускает его локальным runtime с отдельным env-файлом и затем удаляет папку и процесс. На хосте проверяются подключение и чтение БД; расчёты с нативными DLL выполняются в Docker. SQL для специальных случаев меняет только одноразовые тестовые БД.
