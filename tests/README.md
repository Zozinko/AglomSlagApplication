# Автоматические тесты API

Интеграционные HTTP-тесты всех **16 корневых GraphQL-операций** на `/graphql`. Используются настоящий API, математические DLL и PostgreSQL 16 с применением обеих цепочек EF-миграций. Runner — встроенный `node:test`, без npm-пакетов и подмены БД на InMemory.

## Запуск

Нужны Docker с Linux containers, Docker Compose v2, PowerShell, Node.js 22+ и ASP.NET Core runtime .NET 10 для нативной проверки Development-загрузчика. Устанавливать SDK .NET 10 на хосте не требуется: API и migrator собираются существующими Dockerfile проекта. При первой сборке нужен доступ к реестрам образов и NuGet.

Если runtime установлен локально вне PATH, задайте `API_TEST_DOTNET` абсолютным путём к его `dotnet.exe`/`dotnet`. Это позволяет проверять host-запуск без изменения системной установки .NET.

Из корня репозитория:

```powershell
./tests/Run-ApiTests.ps1
```

Скрипт автоматически сохраняет вывод в `logs/last-run.log` и возвращает `0` только при успешном прогоне и удалении тестового стенда, иначе — ненулевой код. При сбое выводит логи API/migrator. `dotnet test` эти тесты не запускает.

Для каждого запуска создаётся Compose-проект `aglom-api-tests-<случайный суффикс>`:

1. Собираются API и migrator из текущего `Soft`.
2. Запускается PostgreSQL с данными в `tmpfs`, собственными БД `SlagMode` и `Auth`, случайным одноразовым паролем со спецсимволами и случайным портом только на `127.0.0.1` для нативного host-процесса.
3. Выполняются настоящие миграции, затем запускается API в `Production` на случайном порту `127.0.0.1`.
4. После готовности API выполняются все `api/*.test.mjs`, затем последовательно `infrastructure/secrets.test.mjs` (SEC-01: секреты, host Development, смена пароля роли) и `infrastructure/runtime.test.mjs` (SQL, миграции, restart, ошибки запуска). Тесты restart повторно получают случайный порт Docker Desktop.
5. В `finally` удаляются контейнеры, сеть и собранные образы именно этого тестового проекта; восстанавливаются прежние переменные тестового окружения.

После намеренного изменения контракта `./tests/Run-ApiTests.ps1 -UpdateSchema` сохраняет SDL из собранного временного API в `requests/schema.graphql`. Обычный запуск не меняет SDL и проверяет его точное соответствие серверу.

Стенд не использует контейнеры `aglom_*`, volume `postgres_data`, порт 5000 или сеть основного Compose. Тесты создают собственные записи, убирают их через `t.after` и не изменяют seed. После принудительного завершения процесса, при котором `finally` не выполнился, оставшийся тестовый проект можно найти через `docker compose ls`; его точное имя видно в выводе запуска.

## Структура и покрытие

| Файл | Операции и сценарии |
|---|---|
| `api/catalog.test.mjs` | `blastFurnaces`, `componentGuides`, `add/update/deleteBlastFurnace`, `add/update/deleteComponentGuide`: CRUD, видимость в списках, все поля состава, отсутствующие ID, запрет удаления используемых записей и разрешение после удаления варианта |
| `api/variants.test.mjs` | `calcVariants`, `calcVariantById`, `add/update/deleteCalcVariant`: все входные скаляры и компоненты, UTC-дата, связи, смена печи, замена компонента с прежним/новым ID, очистка состава, независимость снимка от справочника, каскадное удаление, `null/false` для отсутствующих ID |
| `api/variants.test.mjs` | Неудачные add/update: отсутствующая печь, FK на отсутствующий компонент, повтор компонента; проверяется отсутствие частичного сохранения и сохранность прежнего состояния |
| `api/calculations.test.mjs` | `calculateAglom`: обе разновидности флюса, `id/message`, сериализация всех выбранных числовых полей отчёта. `calculateSlagMode`: все выбранные числовые поля конечны, сумма расходов и доли материалов соответствуют входу; пустой, нулевой, отрицательный суммарный расход и `null` отклоняются |
| `api/contract.test.mjs` | `hello`, `GET /graphql?sdl`, точный набор 5 query / 11 mutation, наличие документов и JSON-примеров каждой операции; синтаксические ошибки, неизвестное поле, обязательные значения, неверный scalar/enum, запрет introspection в Production (`HC0046`) |
| `api/helpers.mjs` | HTTP-клиент с таймаутом, проверка GraphQL errors даже при HTTP 200, чтение документов/примеров, отдельные данные и упорядоченная очистка |
| `api/persistence.test.mjs` | BUG-01/04/09: стабильное время создания, неизвестное историческое время, полные ограниченные связи, валидация имён/дат |
| `api/error-contract.test.mjs` | BUG-07: публичные коды Production без SQL, входных значений, stack trace и внутренних исключений; ошибка нечислового результата DLL |
| `api/calculation-roundtrip.test.mjs` | BUG-12: исходный расчёт и повтор после сохранения; точный двоичный пример и границы ошибки binary32 для десятичных входов |
| `infrastructure/runtime.test.mjs` | BUG-01/04/06/07/09/11: SQL-тип/старое время, restart, родитель/дети, обновление прежней схемы и snapshot, настоящий сбой БД при замене состава, неверный пароль каждой БД, неправильная конфигурация, остановленный PostgreSQL, неуспешный migrator, Development и реальный альтернативный порт |
| `infrastructure/secrets.test.mjs` | SEC-01: обязательные настройки, Git ignore, отсутствие вложенных env и секретов в образах, нативный запуск Development из env-файла, приоритет окружения и прежние имена строк, ротация существующей роли без потери записей |
| `compose.api-tests.yml` | Изолированные PostgreSQL, migrator и API |
| `Run-ApiTests.ps1` | Сборка, запуск, ожидание готовности, тесты и очистка |

Документы запросов и JSON-входы берутся из `requests/operations` и `requests/examples`; тесты подставляют ID реально созданных объектов. Сравнение сохранённых `float` использует допуск, порядок строк в списках не фиксируется.

`API_TEST_DB_PASSWORD` генерируется runner в environment только на время прогона; Compose без него не запускается. Runner создаёт вложенный env-файл с этим паролем для проверки исключения из build context и удаляет его в `finally`. Host-проверка копирует опубликованный API во временную папку, запускает установленным runtime .NET 10 с локальным env-файлом и очищает папку/процесс. Она проверяет подключение и чтение БД; расчёты с нативными DLL проверяются внутри Docker. Настройка рабочего стенда: [configuration.md](../docs/configuration.md).

`GRAPHQL_TEST_URL` обязателен при непосредственном запуске `.mjs`, адрес по умолчанию отсутствует. Для отладки можно явно указать адрес **собственного изолированного стенда** и запустить выбранный файл:

```powershell
$env:GRAPHQL_TEST_URL = 'http://127.0.0.1:<порт-тестового-API>/graphql'
node --test --test-reporter=spec tests/api/variants.test.mjs
```

## Границы и известные дефекты

Прежний тест `HC0018` заменён проверкой успешного update со старой/новой печью. Документ `UpdateCalcVariant.graphql` снова выбирает `blastFurnace`.

`saveTime` теперь включён в сравнение отката; стабильность после update/restart и хранение в SQL проверяются отдельно. Для старых записей ожидается `null`.

Проверки расчётов проверяют HTTP-контракт, сериализацию и выводимые из входа суммы/доли. Они не заменяют утверждённые предметные эталоны математических DLL. Auth, импорт и другие возможности из `TODO.md`, которых ещё нет в текущем API, не считаются реализованными или покрытыми.
